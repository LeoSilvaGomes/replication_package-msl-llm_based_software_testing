# Figures of the systematic mapping study on LLM-based software testing

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24570288.svg)](https://doi.org/10.5281/zenodo.24570288)

Data and code that generate every figure of the paper **What Do We Know About LLM-Based Software Testing?**, a systematic mapping study (SMS) on the use of large language models (LLMs) in software testing.

Every number in the figures is computed from the CSV files in `data/`. No notebook contains hard-coded values: to change a figure, fix the CSV and run the notebook again.

## About the study

The mapping covers **501 primary studies** published between **2023 and 2026**, selected from 8,266 records retrieved from six databases (ACM Digital Library, IEEE Xplore, Web of Science, ScienceDirect, Scopus and SpringerLink). Each study was read in full and coded for:

- the **testing activities supported by the LLM**, organised in a taxonomy of four stages and thirteen activities;
- the **prompt-engineering** and **fine-tuning techniques**;
- the **model vendors** and the **architecture** (single-agent or multi-agent);
- the **generated artifact**: for test instructions, inputs, oracles and code, what the LLM receives, who consumes the result and how it is validated;
- **demographics**: venue type, research type and author affiliation.

### Activity taxonomy

| Stage | Activities |
|---|---|
| T1 Requirements Management | A1 requirement extraction · A2 element localization |
| T2 Artifact Generation | A3 test code · A4 test instruction · A5 test input · A6 test oracle |
| T3 Verification and Prioritization | A7 semantic judgment · A8 prioritization |
| T4 Report and Regression | A9 test repair · A10 test improvement · A11 validation · A12 suite quality · A13 log analysis |

## Folder structure

```
graficos/
├── data/           input data (CSV): the single source of every number
├── scripts/        shared Python modules (data loading, colour palettes, batch run)
├── geral/          overview: demographics, activities, stages, trends and vendors
├── input/          artifact A5: test inputs
├── code/           artifact A3: test code
├── instruction/    artifact A4: test instructions
└── oracle/         artifact A6: test oracles
```

Each figure folder holds one notebook per figure. The notebook saves the image as PNG and, in most cases, also as PDF, in the same folder.

### `data/`

| File | Content |
|---|---|
| `tabela_de_codigos.csv` | One row per study (501). Year, prompt-engineering techniques (`PE1`–`PE11`), fine-tuning (`FT1`–`FT5`), stages and activities (`T1(A1) T2(A3, A5)`), vendors (`M1`–`M11`) and architecture (`AR1`, `AR2`). |
| `legenda_dos_codigos.csv` | Meaning of each code in the table above. |
| `tabela_de_codigos_artefatos.csv` | One row per study, with 13 columns on the generated artifact (format, consumer, context, feedback loop, language...). Studies that do not generate the artifact have `-` in the column. |
| `legenda_dos_codigos_artefatos.csv` | Meaning of each code in the artifact table. |
| `dados_demograficos.csv` | The first seven columns of the extraction table: title, year, venue type, research type, affiliation and venue. |
| `insumo_graficos.csv` | Long format (one row per study and code), generated by `scripts/dados.py`. |
| `codigos_artefatos_com_duvida.csv` | Fields of the artifact table where the extraction text did not settle the code (see *Limitations*). |
| `celulas_substituidas_por_traco.csv` | Cells of the extraction table that did not answer their research question and were replaced by `-`, with the original text. |

### `scripts/`

| File | Purpose |
|---|---|
| `dados.py` | Reads `tabela_de_codigos.csv` and returns the codes of each study as lists; counts studies per code; regenerates `insumo_graficos.csv`. Run directly, it checks the table. |
| `dados_artefatos.py` | Reads the artifact table: counts per code, cross-tabulation of two columns, and techniques of the studies carrying an activity. |
| `paleta.py` | Teal palette of the overview figures (ramp interpolated in CIELAB space). |
| `paleta_grupos.py` | One colour family per artifact: green (input), red (code), blue (instruction) and orange (oracle). |
| `upset_compat.py` | Patch that makes `upsetplot` work with current pandas. Not used by the notebooks of this version. |
| `gerar_graficos.py` | Runs every notebook and rewrites the images. |

## How to reproduce

Requires Python 3.11 or later.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/gerar_graficos.py
```

To generate only some groups, pass the folder names: `python scripts/gerar_graficos.py code oracle`.

The notebooks can also be opened in Jupyter or VS Code and run cell by cell. They must run with their own folder as the working directory, which is the default in those editors.

Folder, file and variable names are in Portuguese, the working language of the authors; figure labels are in English, as in the paper.

## Limitations

- **Artifact coding.** The 13 columns of `tabela_de_codigos_artefatos.csv` were coded from the text of the authors' extraction table, with the help of an LLM-based assistant following written rules for each dimension. Where the text did not settle a code, the most plausible one was chosen and the field was recorded in `codigos_artefatos_com_duvida.csv`.
- **Architecture.** The `Architecture` column is empty for 111 studies, which are not counted as multi-agent in the trends series.
- **Code language.** For 46 studies the extraction does not state the language of the generated code (code `LG0`); they do not appear in the language figure.
- **Year.** The demographic figure uses the year of the extraction table; the others use the year of the code table. The two differ for six studies.
